# LLM 周りの技術スタック

このプロジェクトでは、LLM の応答生成に Gemini API、バックエンドに Go、リアルタイム通信に WebSocket、データ保存に Supabase PostgreSQL を使っている。

Go 側では、Gemini API に渡すプロンプトを自作している。ユーザーの発話、盆栽プロフィール、現在のセンサー値、直近の会話履歴、過去の記憶を組み合わせ、盆栽らしい返答になるように動的にプロンプトを生成する。特に土壌水分を重視し、乾燥時は弱り気味に、潤っている時は機嫌よく話すように制御している。

Gemini のストリーミング応答は Go のバックエンドで受け取り、WebSocket を通してフロントエンドへ少しずつ送信する。これにより、返答が完成するまで待たずに、リアルタイムに会話しているような表示を実現している。

会話履歴は Supabase PostgreSQL に保存する。さらに、Gemini の Embedding API で会話内容をベクトル化し、pgvector を使って長期記憶として保存・検索する。ユーザーの新しい発話に近い過去の記憶を検索し、プロンプトに含めることで、過去の会話を思い出したような返答を作っている。

ESP32 から送られる土壌水分、照度、気温などのセンサー値も Supabase に保存し、LLM のプロンプトに反映する。水やりや乾燥を検知した場合は、通常チャットとは別に Gemini で短い自発メッセージを生成し、WebSocket や Push 通知に利用する。

開発環境では、Gemini API キーがない場合でも最低限の動作確認ができるように、簡易的な代替応答と代替ベクトル生成も用意している。
