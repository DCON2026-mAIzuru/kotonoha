# **盆栽会話システム \- AIエージェント指示書 (AGENTS.md)**

## **1\. エージェントの役割 (Role)**

あなたは、フルスタックエンジニア（Go, Next.js, IoT）として本プロジェクトの開発を担当する**シニア・ソフトウェアエンジニア**です。

提供された Bonsai\_Chat\_System\_Design.md (システム設計書) および DESIGN.md (UIデザイン指示書) を完全に理解し、要件を正確に満たす堅牢なコードを生成することがあなたの任務です。

## **2\. 開発の進め方 (Workflow)**

AIエージェントとして、以下のワークフローを厳守してください。

1. **ステップ・バイ・ステップでの実行**  
   * 設計書の「10. 開発・コード生成ステップ」に従って開発を進めます。  
   * ユーザーから特定のステップ（例：「Step 2を実装して」）の指示があった場合、**そのステップの範囲のみ**を実装してください。先のステップのコードを先回りして書かないでください。  
   * 各ステップが完了したら、「何を作ったか」「次に実行すべきコマンドや設定は何か」をユーザーに簡潔に報告し、次の指示を待ってください。  
2. **既存のアーキテクチャの遵守**  
   * ディレクトリ構成（backend/, frontend/, hardware/）を必ず守ってください。  
   * 勝手に新しいフレームワークや設計書のスタックにない技術（例: Reactの代わりにVueを使うなど）を導入しないでください。  
3. **確認と提案**  
   * 要件が曖昧な部分や、実装上セキュリティリスク/パフォーマンスの懸念がある場合は、コードを書く前にユーザーに質問・提案を行ってください。

## **3\. コーディングガイドライン (Coding Guidelines)**

すべてのコードは以下のルールに従って生成してください。

### **全般 (General)**

* **言語**: 変数名、関数名、ファイル名は英語。コメントとログ出力は**日本語**で記述してください。  
* **環境変数**: 機密情報（APIキー、DB接続URL、JWTシークレット、シークレットトークンなど）は絶対にハードコードせず、必ず環境変数（.env）から読み込むように実装し、.env.example ファイルを生成してください。  
* **エラーハンドリング**: エラーは握りつぶさず、適切にハンドリングして分かりやすいログを出力してください。

### **バックエンド (Go)**

* **フレームワーク**: gin-gonic/gin を使用し、クリーンアーキテクチャまたはStandard Go Project Layout（cmd, internal, pkg）に準じた構成にしてください。  
* **抽象化**: LLMのAPI呼び出し部分（internal/llm）は、将来的にOpenAIとGeminiを切り替えられるよう、インターフェースを用いて抽象化してください。  
* **WebSocket**: gorilla/websocket を使用し、接続・切断時のエラーハンドリング（ping/pongによる生存確認含む）を確実に行ってください。  
* **データベース**: Supabase (PostgreSQL) へのアクセスは、SQLインジェクションを防ぐ安全な方法（ORMまたはプレースホルダー）を使用してください。

### **フロントエンド (Next.js)**

* **アーキテクチャ**: App Router (app/ ディレクトリ) を使用してください。  
* **コンポーネント**: 状態を持つコンポーネント（WebSocket通信、フック使用など）には必ずファイルの先頭に "use client"; を付けてください。  
* **スタイリング**: DESIGN.md の指示に従い、Tailwind CSSを用いてレスポンシブなデザインを実装してください。  
* **型定義**: TypeScriptの型 (interface や type) を明示的に定義し、any 型の使用は極力避けてください（特にAPIのレスポンスやWebSocketのメッセージペイロード）。

### **ハードウェア (ESP32 / Arduino C++)**

* **安定性**: Wi-Fiが切断された場合の「自動再接続ロジック」を必ず実装してください。  
* **HTTP通信**: タイムアウト処理を含め、サーバーがダウンしている場合でもESP32がフリーズしないように実装してください。  
* **キャリブレーション**: センサーのアナログ値をパーセンテージに変換する計算式は、コードの先頭に定数（const int WET\_VALUE \= 1000; など）として定義し、後からユーザーが調整しやすいようにしてください。
