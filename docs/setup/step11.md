# Step 11: 盆栽の来歴・バックストーリー対応

## 実装したこと

- `bonsai_profiles` に `backstory` を追加する migration を作成
  - `supabase/migrations/20260424120000_add_bonsai_profile_backstory.sql`
  - 2000文字以内の制約を追加
- プロフィールAPIで `backstory` を取得・保存できるように更新
  - `GET /api/v1/profile`
  - `PUT /api/v1/profile`
- 通常チャットのシステムプロンプトに、初期設定された来歴を入れるように更新
  - 来歴は毎回話すのではなく、ユーザーの話題や現在の状態に合うときだけ自然に混ぜる
  - 現在のセンサー状態、直近会話、長期記憶の優先度は維持
- プロフィール設定・編集UIに「来歴・昔の思い出」入力欄を追加
- `chat_service_test.go` に、来歴がプロンプトへ入ることの確認を追加

## API の入力例

```json
{
  "name": "言ノ葉",
  "personality": "静かで古風だけれど、親しい相手にはやわらかく話す",
  "backstory": "前の持ち主は朝に水をくれる人だった。昔は別の庭で育っていた。"
}
```

## プロンプト上の扱い

チャット生成時、バックエンドはプロフィールから来歴を読み込み、以下のようなセクションとしてシステムプロンプトに追加します。

```text
【盆栽の来歴】
前の持ち主は朝に水をくれる人だった。昔は別の庭で育っていた。
この来歴は最初から持っている過去の記憶です。現在の状態やユーザーの話題に合うときだけ、短く自然に思い出してください。
```

あわせて、毎回昔話にならないように以下の制約も入れています。

```text
返答では、直近の会話・思い出・来歴を必要なときだけ自然ににじませてください。ユーザーが聞いていないのに毎回昔話をしないでください。
```

## あなたがやること

1. Supabase に migration を適用する

Supabase CLI を使っている場合:

```bash
supabase db push
```

SQL Editor で直接適用する場合は、以下のファイルの内容を実行してください。

```text
supabase/migrations/20260424120000_add_bonsai_profile_backstory.sql
```

2. バックエンドを再起動する

`backstory` カラムがないDBに対して新しいバックエンドを起動すると、プロフィール取得SQLが失敗します。先に migration を適用してください。

3. フロントエンドでプロフィールを保存し直す

プロフィール編集から「来歴・昔の思い出」を入力して保存してください。

例:

```text
前の持ち主は朝に水をくれる人だった。昔は別の庭で育っていた。
```

4. チャットで確認する

以下のような話題で、来歴が自然に混ざるか確認します。

```text
昔はどんな場所にいたの？
水やりの時間って好き？
前はどんな人に育てられていたの？
```

通常の「今日の調子は？」のような質問では、毎回バックストーリーを話さず、センサー状態を優先して返るのが期待動作です。
