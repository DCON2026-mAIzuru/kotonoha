# Step 7: RAGチャットとプロンプト動的生成 構築メモ

## 今回追加したもの

- `ChatService` の動的システムプロンプト生成
  - `bonsai_profiles` から名前・性格を取得
  - `sensor_data` から現在の身体状態を文章化
  - `chat_history` の直近履歴をプロンプトへ反映
  - `bonsai_memories` から関連記憶を検索して RAG 文脈として注入
- `chat_history` の直近取得処理
  - `ListRecentChatHistoryByUserID` を追加
- センサー異常値ハンドリングの強化
  - 極端値をそのまま会話不能エラーにせず `invalid` 状態として保存
  - 異常時は「盆栽の感覚の違和感」として次回チャットににじませる
  - `invalid` 状態のセンサー値では水やりイベントを発火しないように調整
- Step 7 向けテスト
  - 動的プロンプトにプロフィール・履歴・記憶・異常値情報が入ることを確認
  - 異常センサー値が `invalid` になることを確認

## この段階で変わったこと

通常チャット時、LLM には単なるユーザー発話だけではなく、以下をまとめたシステムプロンプトが渡るようになりました。

- 盆栽の名前
- 性格・口調
- 現在のセンサー状態
- 直近の会話履歴
- 類似検索で見つけた過去の記憶

これにより、返答が「今の体調」「最近の流れ」「以前の出来事」を踏まえたものになりやすくなります。

## プロンプトに入る情報のイメージ

### プロフィール

```text
あなたの名前は「言の葉」です。性格や口調は「古風なおじいちゃん」です。
```

### 現在の状態

正常時の例:

```text
土壌水分量 58.0%、照度 12000.0 lux、気温 24.3℃、最終計測 2026-04-14 10:30。今のところ大きな違和感はありません。
```

未受信が続いた例:

```text
土壌水分量 58.0%、照度 12000.0 lux、気温 24.3℃、最終計測 2026-04-14 09:50。ただし新しい感覚がしばらく届いておらず、少し感覚が鈍っています。
```

異常値が混ざった例:

```text
土壌水分量 40.0%、照度 1200.0 lux、気温 -50.0℃、最終計測 2026-04-14 10:30。ただし一部の感覚が乱れており、数値は参考程度に扱ってください。気温は -127.0℃ と極端に触れています。
```

### 直近の会話

```text
- ユーザー: 今日はどんな気分？
- 盆栽: 朝の光が気持ちいいです。
- 出来事: お水をもらえて助かりました。
```

### 思い出した過去の記憶

```text
- ユーザー: 先週は日当たりのよい窓辺に移してくれた
  盆栽: 葉がのびのびしました
```

## 追加した内部API

- `PostgresStore.ListRecentChatHistoryByUserID(ctx, userID, limit)`
  - 直近の会話履歴を新しい順で取得し、プロンプト用に時系列へ並べ直して返す
- `ChatService.buildChatSystemPrompt(...)`
  - プロフィール、センサー状態、短期履歴、長期記憶を統合して LLM 用のシステムプロンプトを組み立てる

## 異常値ハンドリング方針

- `moisture_percent` が `0〜100` を外れた場合
  - 保存時は範囲内に丸める
  - 元の値は `raw_payload` に残す
  - `sensor_status=invalid`
- `light_lux` が負値の場合
  - 保存時は `0` に丸める
  - 元の値は `raw_payload` に残す
  - `sensor_status=invalid`
- `temperature_celsius` が `-50〜100` を外れた場合
  - 保存時は範囲内に丸める
  - 元の値は `raw_payload` に残す
  - `sensor_status=invalid`

通常チャット側では、この `invalid` 状態を「盆栽の感覚が乱れている」という表現の材料に使います。

## 現時点の注意

- RAG の対象は `bonsai_memories` に保存済みの 1 往復単位の要約
- 検索結果が 0 件でもチャット自体は通常通り続行する
- 埋め込み生成や類似検索に失敗しても、チャット全体は止めずにフォールバックする
- 直近履歴には `role=event` も含まれるため、水やり通知の文脈も通常チャットに反映されうる
- センサー異常値は API エラーではなく会話コンテキストに変換する方針にしたため、以前より保存されるケースが増える

## 想定確認手順

1. `backend/` でサーバー起動
2. プロフィール API で盆栽の名前と性格を登録
3. `POST /api/v1/sensor` で通常値または異常値を保存
4. WebSocket で `/ws/chat?token=...` に接続
5. 関連する話題を数回送って `bonsai_memories` に会話を蓄積
6. 似た話題を再度送って、過去の出来事を踏まえた返答になることを確認
7. センサー未更新または異常値保存後に話しかけて、「感覚が鈍い」「感覚が乱れている」ような表現が返答ににじむことを確認
