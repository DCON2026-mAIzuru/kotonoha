# システム構成

Kotonoha はセンサー値や会話履歴を使って盆栽との対話を行うシステムです。構成図は [システム構成図](system-architecture-diagram.md)、起動方法は [ローカル開発・運用](../setup/local-development.md) を参照してください。

## コンポーネント

| コンポーネント | 役割 |
| --- | --- |
| `frontend/` | Next.js App Router による画面、Supabase Auth、WebSocket チャット、PWA・Push 購読、画像診断と読み上げの操作 |
| `backend/` | Go / Gin による REST API と WebSocket、認証、会話・センサー・診断・通知の処理 |
| `supabase/` | Auth と PostgreSQL / pgvector。マイグレーションをファイル名の昇順で適用する |
| `DL/` | FastAPI 画像診断サービス。バックエンドから画像を受け、結果とヒートマップを返す |
| VOICEVOX Engine | バックエンド経由でテキストを音声に合成する外部サービス |
| `esp/`、`hardware/` | ESP32 のスケッチとセンサー送信シミュレーター。各スケッチの構成は [センサー送信](../setup/sensors.md) を参照 |

## 主なデータフロー

- 会話では認証済みユーザーのプロフィール、センサー状態、直近履歴を使ってプロンプトを組み立て、応答を WebSocket でストリーミングします。生成元はGeminiまたはOpenAI互換サーバーを設定できます。埋め込みを設定した場合はベクトル記憶の検索・保存も行います。埋め込みを無効にしても通常の会話履歴は保存します。LLM未接続時の `disabled` はエラーを返します。
- センサー API は値を保存し、水分上昇・低下を判定します。イベント時には応答を生成して WebSocket に配信し、設定済みの購読先へ Web Push を試みます。判定条件は [センサー送信](../setup/sensors.md) を参照してください。
- 画像診断ではバックエンドが画像を DL サービスへ送り、診断結果と成果物を保存します。DL サービスとバックエンドの成果物はそれぞれローカルディレクトリに置かれるため、運用環境の永続化を考慮してください。
- 音声読み上げはバックエンドが VOICEVOX Engine に接続します。エンジン自体は別途起動が必要です。

## データと認証

PostgreSQL にはプロフィール、センサー、チャット履歴、ベクトル記憶、Push 購読、診断を保存します。具体的なスキーマは `supabase/migrations/` を参照してください。REST API は原則 Supabase のアクセストークンを使い、センサー送信は共有トークンとユーザー ID のヘッダーで認証します。詳細は [API と WebSocket](../api.md) を参照してください。
